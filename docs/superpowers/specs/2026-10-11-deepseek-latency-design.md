# 识别延迟与 DeepSeek 集成设计

用户已确认保留 FunASR、优化队列、在 GUI 配置 Key，并要求识别后能够自动触发 AI。验证仅使用本地合成音频与模拟接口，不调用真实 DeepSeek，不采集会议内容。

## 架构与范围

音频设备 → 有界音频队列及单个分段线程 → 有界识别队列及单个推理线程 → Tkinter 主线程 → 可选自动/手动 DeepSeek 流式请求 → 回答区。

API Key 在 GUI 遮罩输入，仅保留在进程内存。自动触发默认关闭，用户勾选后每个完整识别段发送到 DeepSeek；界面明确说明会上传文字。仅发送当前语音段，手动模式发送编辑后的当前识别文本，不自动上传历史。端点固定为官方 HTTPS 服务，不允许自定义端点转发 Key。

使用官方当前模型名 deepseek-flash / deepseek-v4-pro；默认 flash、非思考、流式、限制输出长度。请求具有超时和取消机制，不自动重试收费请求。后来的问题取消并替换旧问题；请求编号防止旧回答写回。并发请求采用固定工作线程，待处理任务最多一个。

## 识别优化

删除无人消费的无界音频积压；音频回调只复制数据并非阻塞入队。识别缓冲保留 NumPy 块，避免逐采样 Python float。识别队列最多两个待处理段，过载时明确报告丢弃旧段。停止、重载和关闭均使旧任务失效。默认停顿保留 1.2 秒，提供 0.6 秒低延迟快捷设置；测试用样本精确验证停顿与最长段边界。

## 指标和错误

记录队列等待、推理和音频长度；AI 记录首字与完整输出时间。GUI 主线程读取所有 Tk 变量，后台只通过事件队列更新。UI 每次轮询处理有限数量事件。识别失败、队列过载、Key 缺失、认证失败、限流、断流与超时均给出明确状态；异常不打印 Key 或请求正文。

## 验收

本地测试覆盖语音分段、队列上限、停止后的旧回调、CPU 状态、有序推理、SSE/中文/心跳/错误/超时/取消、自动触发开关及旧请求隔离。GUI 验证 Key 遮罩、自动触发和流式显示。合成音频和延迟受控的模拟接口生成性能报告，明确区分模拟延迟与真实模型/云服务速度。不结束已有用户进程，不安装依赖，不推送未验证改动。
